# Human Gerbals: project plan

Goal: a KSP2 Redux mod that replaces kerbals with human astronauts called Gerbals, covering 3D
models, textures, hair, eyes, helmets, names, voices and body sound effects, without editing any
stock game file.

Companion documents: `game-reference.md` (asset contract), `audio-events.md` (sound event table).

## 1. What the teardown established

1. **Appearance is data driven.** A kerbal is assembled at runtime from separate addressable prefabs
   (body, head, eyes, hair, helmet, facial hair, glasses) selected from JSON tables labelled
   `kerbal_variety`. Adding a human set means adding prefabs with new keys and pointing the tables at
   them. No stock prefab needs to be replaced.
2. **The tables cannot be overridden by shipping same-named JSON.** The loader rejects duplicated
   fixed-name files and Addressables always resolves a duplicated key to the stock catalog. The mod
   therefore overrides the lookups with four small Harmony patches (`Code/VarietyPatches.cs`).
3. **The skeleton is fixed.** Heads and facial hair are re-skinned onto the body rig by bone name;
   eyes are re-parented by bone name; the avatar is Generic, so all 166 clips address bones by
   path. Human meshes must be rigged to the exact kerbal bone hierarchy. Bone proportions can differ
   only where the clips do not animate bone position (see Phase 3).
4. **Sounds are Wwise events.** 53 body/suit events plus voice events selected through two RTPCs.
   Event IDs are name hashes, so a runtime remap table (`Code/AudioRemapPatches.cs`) can redirect
   every stock kerbal event to an event in a mod-authored bank that SpaceWarp2 loads for us.
5. **Toolchain is fixed by the install.** Redux 0.2.9 beta runs Unity 6000.5.8f1 and Wwise
   2021.1.10. Bundles must come from a Unity 6 editor chosen by the Redux SDK Manager; banks from
   Wwise 2021.1.x. The public wiki's "Unity 2022.3.5f1" is out of date for this build.

## 2. Architecture

```
mods/HumanKerbals/                 (folder names are what SpaceWarp2 scans, verified in its code)
  swinfo.json                      mod manifest (spec 3.0, main_assembly HumanKerbals.dll)
  HumanKerbals.dll                 plugin: loads data, installs Harmony patches
  addressables/catalog.json        + StandaloneWindows64/*.bundle built by the Unity project
  localizations/*.csv              wording overrides ("Kerbal" -> "Gerbal") where wanted
  assets/
    data/human_variety.json        category tables, weighted tables, names, hero overrides, audio remap
    soundbanks/HumanKerbals_*.bnk  Wwise events + media for human SFX and voices
  Patches/*.lua                    optional Patch Manager tweaks (eva_kerbal part data)
```

In the Unity project this is `Assets/HumanKerbals/`: `Code/` (asmdef + plugin), `Copied/` (copied
verbatim into the mod root: `localizations`, `Patches`, `assets/data`, `assets/soundbanks`), the
addressable groups, and `Pipelines/` generated by the SDK. `unity/Assets/Editor/HumanKerbalsBatch.cs`
runs the SDK's create/build/deploy steps headless (`tools/unity_batch.ps1`).

Runtime flow:

1. SpaceWarp2 registers the mod, loads the DLL, the addressables catalog, the soundbanks and the CSVs.
2. `HumanKerbalsPlugin.OnPreInitialized` reads `human_variety.json` and patches
   `KerbalVarietySystem.GetVarietySubCategoryByRangeRule`, `GetWeightedOptionsArrayByName`,
   `VarietyUtils.GenerateSurname`, `GenerateCustomKerbalAttributesFromRawData` and the
   `AkSoundEngine.PostEvent` overloads.
3. When the game generates or spawns a kerbal, the patched lookups hand back human prefab keys, the
   stock `Kerbal3DModel` loads `head_human_m_01.prefab` and friends from the mod catalog and assembles
   them on the stock rig, and every kerbal sound event is rewritten to its human counterpart.

Everything else (portraits, IVA, EVA physics, roster UI, saves) is untouched. Saves store attribute
keys, so a save created with the mod references human keys; removing the mod would make those kerbals
fall back to errors, which is normal for appearance mods and should be stated in the README.

## 3. Phases

### Phase 0: environment (done 2026-09-03)

Status: complete. Installed Unity Hub 3.21 (`C:\Program Files\Unity Hub`), Unity 6000.5.8f1 and,
unintentionally through the Hub's first-run auto-install, 6000.6.0f1 (safe to remove from the Hub),
Blender 5.2 (`C:\Program Files\Blender Foundation\Blender 5.2`) and the Redux SDK CLI
(`tools\sdk\redux-sdk-cli.exe`). The Unity project `unity\` was created from template 26w35b, the
game import (`redux-sdk-cli setup`) and the headless `SetupMod` / `BuildForPlayer` steps work without
signing in to Unity, the plugin DLL compiles, and the staged mod in `<KSP2>\mods\__Testing\HumanKerbals`
registers in the game log (`tools\verify_in_game.ps1`). The mod asmdef additionally references
`Unity.Addressables` and `Unity.ResourceManager` so the plugin can validate prefab keys at startup.

What the staged mod already does in the game (verified in the log on 2026-09-03): the plugin loads
`human_variety.json`, installs the Harmony patches, prunes every category whose human prefabs do not
exist yet (all of them for now, so stock kerbal bodies stay), and keeps the tables that only need data:
human skin tones (`SKINCOLOR_OPTIONS_WEIGHTED`), the English first-name list and the human surnames.
So new kerbals generated with the mod installed already get human names and skin colours on kerbal
bodies. Remove `mods\__Testing\HumanKerbals` to go back to stock behaviour.

Original checklist, kept for reinstalling on another machine:

- Install the Redux SDK Manager v0.4.2 (`redux-sdk-gui.exe`) from
  https://github.com/KSP2Redux/Redux-SDK-Manager/releases. It installs Unity Hub, Git and the Unity
  version matching the installed Redux (pick the version closest to 0.2.9 beta; enable snapshot
  versions in its settings if the beta build needs the snapshot template, which is on Unity 6000.5.x).
- Create the project into `unity/` with the manager ("New"), let it import the game (5 to 10 minutes),
  then "Modding > Create New Mod" with Mod ID `HumanKerbals` and code generation enabled. Copy
  `mod/HumanKerbals/Code/*.cs` into `Assets/HumanKerbals/Code` and the `assets/data`,
  `assets/localizations`, `assets/soundbanks` folders into the mod's `Copied` folder. Run
  "Modding > Publicize Assembly-CSharp.dll" so the patches can reference private types.
- Install Blender 4.x (not present on this machine), Wwise Launcher with Wwise 2021.1.13 (free
  license, 200-sound limit per bank is fine), and optionally AssetRipper (clip export) and
  vgmstream (listening to stock `.wem`).
- Verify the loop: build the empty mod, "Test Selected Mods in Editor" or deploy the zip into
  `<install>\mods`, check `Ksp2.log` for `Registered plugin: HumanKerbals` and no Harmony errors.

### Phase 1: playable human on the kerbal rig (the milestone that proves the pipeline)

Status 2026-09-03: MILESTONE REACHED. The game builds roster kerbals with the human parts and
photographs them with its own portrait booth (`docs/images/portrait_jeb_phase1.png`,
`docs/images/portrait_valentina_phase1.png`). Lessons that are now baked into the tooling: the body
root needs the `KerbalEVAModelsRoot` tag; skinned meshes must list only the bones they use (Blender
exports a cluster per bone, and the game rejects a mesh whose bone list contains anything missing);
single-mesh attached parts need a wrapper root; FBX child transforms need the frame recipe in
`docs/game-reference.md`. Kerbals that pre-date the mod in a save are upgraded through `legacyRemap`.

The pipeline is proven with a procedurally generated stylised human.
`tools/blender_make_human.py` builds suit, backpack, two heads, two eye sets, helmet and four
hairstyles on the rig and exports ten FBX files; `HumanKerbalsBatch.ImportModels` turns them into
addressable prefabs; `tools/compare_rig.py` confirms the imported bones match stock exactly; the
game loads the mod catalog and reports all human categories active. In-game verification runs
through `tools/verify_in_game.ps1 -TestLoad`, which launches the game with `-humankerbals-test`:
the plugin's `TestHooks` auto-load the newest save, every roster kerbal is built and photographed by
the stock photo booth, and the portraits land in `logs/portraits`. Remaining Phase 1 work is art
quality (replace the primitive-based meshes with sculpted ones in `blender/human_rig.blend`, keeping
object names and the finalize/export flow), textures, the jumpsuit body, and a visual check of the
EVA/IVA views (only the portrait booth has been verified automatically; the helmet prefab structure
matches stock but has not been seen in flight yet). Skin colour: materials use Unity's Standard
shader with the tone baked into the material, so the game's per-kerbal `_RandomColor` tint (only
applied to `KSP2/Standard Character` materials) has no effect yet; switching the head material to the
game's shader through a Linked Addressable is the way to get per-kerbal skin tones from
`SKINCOLOR_OPTIONS_WEIGHTED`.

Deliver one male and one female head, one spacesuit body, one helmet, one eye set, two hairstyles.

1. Import `reference/meshes/mesh_spacesuit_01.obj`, `mesh_male_head_01.obj`, `mesh_male_eyes_01.obj`
   and `reference/hierarchies/body_spacesuit_01.json` into Blender to recreate the kerbal armature
   at game scale (a script that builds the armature from the JSON is a good first task).
2. Model or adapt a stylised human at kerbal proportions (short legs, big head are baked into the
   rig for now). Skin the suit body to the armature, the head to the 18 head/face bones, keep eyes as
   two eyeballs plus four eyelids parented (not skinned) to `bone_kerbal_l_eye` etc.
3. Export FBX per part with the rig included; in Unity build prefabs that mirror the stock ones:
   `body_human_spacesuit_01` (root with Animator using `animtree_kerbal_eva` via a Linked Addressable,
   skeleton, skinned meshes, tags `KerbalEVAModelsRoot`/`KerbalJetpackRoot`, reentry meshes can be
   copied later), `head_human_m_01`, `head_human_f_01`, `eyes_human_m_01`, `eyes_human_f_01`,
   `helm_human_spacesuit_01`, `hair_human_*`. Materials use `KSP2/Standard Character` linked from the
   game; author `_MainTex`, `_BumpMap`, `_OcclusionMap`, `_MaskTex` per part.
4. Mark the prefabs addressable with exactly those keys (lower case, `.prefab` suffix) in the mod's
   addressables group, build, deploy, and spawn a kerbal at KSC. Check the log for
   `ReplaceOldBonesWithNewBonesInSkinnedMesh` errors (a bone name mismatch) and
   `AttachToNamedParent` warnings.
5. Tune `SKINCOLOR_OPTIONS_WEIGHTED` in `human_variety.json` (human tones are already there) and
   decide whether skin tint goes through `_RandomColor` + mask or through painted albedo.

Exit criteria: roster, EVA, IVA portrait and photobooth all show humans, no red log lines from the
variety system, jetpack and helmet toggles work.

### Phase 2: sound

Status 2026-09-04: the runtime side is done and the first generated bank ships. Every kerbal sound
event is remapped by the word rule Kerbal -> Gerbal (`audioWordSwap`; a bank authored with the
`Play_An_Gerbal_*` names is picked up automatically, missing events stay stock), all sixteen
`AkSoundEngine.PostEvent` overloads are patched, and `tools/wwise_bank_write.py` writes bank-format-140
soundbanks with embedded PCM from WAV files, so simple SFX/voice banks no longer need the Wwise
authoring tool. The English narration that says "Kerbal" (10 lines, 15 words) now says "Gerbal":
`tools/vo_gerbal.py` transcribes the voice-over, shortens the /k/ aspiration into a /g/, and generates
`assets/soundbanks/HumanKerbals_narration.bnk` plus `assets/data/narration_remap.json`
(`docs/audio-events.md`). In-game check: `tools\verify_in_game.ps1 -AudioTest`.

Remaining:

1. Extract and listen to the stock kerbal SFX and voice media (`tools/vgmstream`) to match timing
   and loudness.
2. Produce the human SFX and voice clips and build `HumanKerbals_sfx.bnk` with
   `tools/wwise_bank_write.py` (one clip per event; random variation and the two voice RTPCs
   `kerbal_voice_selection` 0 to 10 and `kerbal_voice_type` 0 to 2 need either the Wwise 2021.1
   authoring tool in `audio/wwise/` or an extension of the writer to random containers and RTPCs).
3. Resolve the 13 unnamed events in `kerbal_sfx_events.bnk` and the chatter events in
   `u_states_UI_music_utilities_events.bnk` (wwiser dump), add them to `stockAudioEvents`.
4. Narration polish: the ten edited lines were validated by re-transcription only; listen to
   `reference/audio/edited/*.wav` and tune `KEEP_BURST` / `PREVOICE` in `tools/vo_gerbal.py` if a
   word still reads as "Kerbal" (the "Kerbal Space Program" phrases are the hard ones).

### Phase 3: human proportions (optional, the hard part)

Option A, runtime offsets: attach `Code/HumanProportions.cs` to the body prefab and re-apply human
bone offsets in LateUpdate for bones whose stock position curves are constant (thighs, spine, collars,
pelvis, most finger roots). Knees, elbows, shoulders, hands, neck, eyes, jaw and the jetpack arms are
animated in position and will still follow kerbal offsets, so the gain is limited to torso and legs.

Option B, retarget: export all 166 clips with AssetRipper, retarget in Blender to a human-proportioned
copy of the same armature (same names), re-import as clips, rebuild the three animator controllers
inside the mod (the controllers are addressable assets, so the mod can ship its own `animtree_*` and
assign them on the body prefab) and keep every animation event. This is weeks of animation work but
gives real human proportions and posture.

Recommendation: ship Phase 1 and 2 on the kerbal proportions first, then evaluate Option B.

## 4. Risks and how to handle them

| Risk | Mitigation |
| --- | --- |
| Redux beta upgrades change class names the Harmony patches target | Patches are few and log loudly; pin `ksp2_version` max in `swinfo.json` per release |
| Redux updates rebuild bundles on a newer Unity 6 patch | Bundles stay loadable across 6000.x patch versions; rebuild only on a minor bump |
| A future Redux build adds new kerbal categories (e.g. colonist outfits) | `VarietyPatches` only overrides categories present in `human_variety.json`; unknown ones fall through to stock |
| Voice RTPC structure inside stock Wwise is unknown | The mod bank defines its own RTPC curves; only the names must match |
| Portrait camera framing assumes kerbal head size | Adjust head scale in the head prefab or patch `KerbalPhotoBooth` camera offset via prefab patch |
| Human head lacks kerbal lip bones for lipsync | Keep the bones in the rig even if weights are light; expressions still play |
